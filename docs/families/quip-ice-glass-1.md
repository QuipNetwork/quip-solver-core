# quip/ice-glass revision 1

This contract describes a spin glass with a hidden ice. The construction picks edge-disjoint ice tiles in the base topology. It gives each tile edge the strong coupling and each other edge a random glass coupling. A random gauge then hides the tiles.
Its Rust contract is `ising_generators::ice::ICE_GLASS_V1`.
Its vectors are the `cases` section of `crates/quip-solver-conformance/vectors/families/ice_structure.json`.
The construction uses the tile structure of `ising_generators::ice`. That structure gives the tile candidates and the two sides, and `select` picks the tiles.

## Parameter schema

| Tag | Name | Type | Scale | Min | Max |
|---|---|---|---|---|---|
| 1 | zephyr_m | u16 | 1 | 0 | 32 |
| 2 | zephyr_t | u8 | 1 | 0 | 8 |
| 3 | glass_milli | u16 | 1 | 1 | 999 |

The bounds are inclusive and apply to the stored integer.
The pair `zephyr_m` and `zephyr_t` is the lattice shape. The shape `(0, 0)` is the adjacency mode. The shape with both values greater than 0 is the Zephyr mode on the lattice `z(zephyr_m, zephyr_t)`.
`glass_milli` is the size of every glass coupling, in milli units. Any value from 1 to 999 is valid.

## Substream labels

| Label | Draws |
|---|---|
| left | The shuffle of the left side order. One `uniform(i + 1)` value for each `i` from `L - 1` down to 1, where `L` is the number of left spine edges. |
| right | The shuffle of the right side order. One `uniform(i + 1)` value for each `i` from `R - 1` down to 1, where `R` is the number of right spine edges. |
| glass | One `uniform(2)` value for each edge that is not a tile edge, in ascending edge order. |
| gauge | One `uniform(2)` value for each node, in node registration order. |

## Construction steps

Let `n` be the node count of the base topology. Let `g` be `glass_milli`.
Check every operation. An overflow returns code 13, `BoundsExceeded`.
A dense position is the index of a node in the registration order of the base topology.

1. Find the tile candidates of the base topology and its sides. The shape `(zephyr_m, zephyr_t)` selects the mode. Tile edges are the 6 edges of each selected tile. A defect in a topology that admission accepted returns code 12, `TopologyIncompatible`.
2. Set `left_order` to the identity order of the left spine edges. Shuffle it with the Fisher-Yates shuffle (FAM-24) on the stream `left`.
3. Set `right_order` to the identity order of the right spine edges. Shuffle it the same way on the stream `right`. The shuffle of the left order draws first. The two streams are independent.
4. Select the tiles. Select every free tile, which has no spine. Then match the left spine edges to the right spine edges. The matching visits the left spine edges in `left_order`. For each one it tries the right spine edges in the rank order of `right_order`, and it looks for one augmenting path. Each matched pair is one spine tile. The result is the sorted list of tiles. Each tile is four dense positions in ascending order.
5. List the nodes in registration order. List every edge of the base topology as `(min, max)` of its dense positions, in ascending order.
6. Give each tile edge the coupling `+1000`. Visit every other edge in ascending order. Draw `d = uniform(glass, 2)`. If `d = 0`, set the coupling to `+g`. If `d = 1`, set the coupling to `-g`.
7. For each node in registration order, draw `uniform(gauge, 2)`. The value 0 gives the gauge `+1` and the value 1 gives `-1`. Then multiply each coupling `J(u, v)` by the gauge of `u` and the gauge of `v`.
8. Set `h = 0` for every node and the offset to 0.
9. Write the metadata region with the kinds 1 and 2, in that order. All integers are little-endian. The region is the section count 2 as `u16`, then the sections. Each section starts with its kind as `u16` and its payload length as `u32`. The payload follows.

This revision differs from the research generator in these ways:

- The streams are ChaCha8 streams from the stream seed of the family (FAM-22). The research generator used NumPy PCG64 permutations and drew from the raw nonce.
- The matching is the Kuhn matching in the order of `left_order` and `right_order`. The research generator used SciPy matching.
- The adjacency mode finds tiles from the adjacency of the base topology alone. The research generator had no such mode.
- `glass_milli` is any value from 1 to 999. The research generator used 125 or 200.
- The gauge and the tiles are in the metadata region, so a verifier can recover the ice.

The research cohort is not regenerated by this revision.
The archived tiles are valid-candidate evidence only. This revision gives no parity with them.

## Offset

`0`

## Metadata

| Kind | Name | Payload |
|---|---|---|
| 1 | tiles | The tile count as `u32`. Then, for each tile, 4 dense positions as `u32`, ascending, with the tiles in ascending order. |
| 2 | gauge | The node count as `u32`. Then one byte for each node in node order, `0x00` for the gauge `+1` and `0x01` for `-1`. |

The region has two sections, kind 1 then kind 2, and nothing follows them. The gauge count must equal the node count.
The tiles must be ascending and distinct. Each position must be below the node count.
Each tile pair must be an edge of the instance with `J * g_u * g_v = 1000`. The tiles must be edge-disjoint, and each node must be in at most 2 tiles.
Each other edge must have `J * g_u * g_v = +g` or `-g`. Every `h` and the offset must be 0.

## Constraint class

`soft`

This family has no feasibility constraints. Every spin assignment is a valid answer.

## Bounds

| Quantity | At most |
|---|---|
| each `\|h\|` | 0 milli |
| each `\|J\|` | 1000 milli |
| nodes | 131072 |
| edges | 2097152 |
| metadata bytes | 8388608 |
| max degree of the base topology | 32 |

The shape rule: `zephyr_m` and `zephyr_t` are both 0 or both more than 0. A mixed shape gives code 12 at topology admission.
The strong coupling is 1000 and every glass coupling has a size of at most 999, so no product overflows `i32`.
A base topology with a degree of more than 32 returns code 13 at size bounds. This keeps the tile search bounded (FAM-38).
Every other bound is the FAM-37 bound.

## Size bounds

The size bounds are the base topology itself:

```text
N(p, T) = n_nodes(T)
E(p, T) = n_edges(T)
D(p, T) = max_degree(T)
```

The parameters do not change the sizes. If `max_degree(T)` is more than 32, the size bounds return code 13.

## Max retries

`none`

No step retries. Every salt gives an instance when the topology carries tiles.
A topology that carries none gets code 12 at admission, and no salt gives a draw.
